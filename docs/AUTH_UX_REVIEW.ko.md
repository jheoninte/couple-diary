# 로그인·커플 연결 UX 점검 — 2026-11-14

이번 변경은 맥 로컬 미리보기용이다. 사용자 요청에 따라 TestFlight 추가 업로드, 서버 배포, 운영 계정/데이터 변경을 하지 않았다.

## 로그인 방식 판단

이메일/비밀번호는 초기 구현 범위가 작고 특정 소셜 계정에 의존하지 않는다. 다만 비밀번호 관리·메일 전달·복구 문의가 남으므로 가장 편리한 사용자 경험과 같지는 않다. 이번에는 기존 방식을 완성하고, 이후 iOS에서 Apple 로그인을 추가하는 방안을 권장한다. 소셜 로그인을 추가할 때는 기존 Firebase UID와 구매/일기 연결을 보존하는 명시적인 계정 연결이 필요하며 이메일 일치만으로 자동 병합하지 않는다.

자체 계정 시스템만 사용하는 앱은 Apple 심사 지침 4.8의 대체 로그인 요구 예외에 해당한다. Google 등 제3자 로그인을 추가하면 동등한 개인정보 보호 로그인 옵션을 함께 검토해야 한다.

## 변경 사항

- 전용 비밀번호 재설정 화면, 이메일 보존, 일반화된 발송 안내, 스팸함 안내와 60초 재전송 제한.
- 중복 가입은 비밀번호를 복사하지 않고 로그인 화면으로 이동하며 이메일을 유지한다. 비밀번호 일치/최소 길이, 비밀번호 보기, 오류 후 버튼 복구, 한국어 인증 메일 요청, 기존 세션 복원을 제공한다.
- ‘내가 초대하기’와 ‘초대 코드 받음’을 서로 다른 선택으로 표시한다. 16자리 난수의 보안성은 유지하고 네 묶음 표기·코드 복사·사용자가 직접 여는 공유 메뉴를 추가했다. 소문자/공백/하이픈 입력도 받는다.
- 코드는 24시간/한 번 사용, 새 코드 발급 시 이전 코드 만료, 상대방 연결 시 실시간 완료 표시. 기존 일기장을 자동으로 해제하거나 덮어쓰지 않는다.
- 로그아웃·이메일 확인 등 보조 기능은 접힌 계정 메뉴로 이동했다. 보관함이 없으면 숨긴다.

## 실제 발견한 결함

2026111402 설치본의 `login` 및 `couple-connect` 번들에는 외부 gstatic Firebase Auth import가 남아 있었다. Vite 변환기가 `.js?v=...` 파일을 놓쳐 앱 내부 SDK와 CDN SDK가 혼용됐다. 소스 변환에서 쿼리를 제거한 경로를 검사하도록 고쳤다. 빌드 결과에 외부 Firebase SDK가 남으면 빌드를 실패시키는 검사를 추가했다. 실제 1402 아카이브는 이 검사에 실패하고 현재 결과는 통과한다. 아이폰에서의 재검증은 아직 안 했으므로 실기기 해결 완료로 간주하지 않는다.

로컬 에뮬레이터 링크가 절대 URL로 변경된 뒤 `href` 접두사로 찾던 메뉴가 사라져 일기장 초기화가 실패하는 문제도 발견했다. 안정적인 요소 ID로 수정하고 회귀 검사를 추가했다.

## 검증

단위 검사 54개, 구문 검사와 스테이징 웹 빌드/번들 검사를 통과했다. 로컬 Auth 에뮬레이터에서 재설정 링크 발급 → 비밀번호 변경 → 이전 비밀번호 거부 → 새 비밀번호 로그인, 중복 가입 및 잘못된 링크 거부를 확인했다. 두 브라우저 origin의 별도 테스트 계정으로 초대 생성·복사·소문자/하이픈 코드 입력·양쪽 연결 완료·첫 일기 저장·상대방 읽기를 확인했다. 실제 메일함 전달률, iOS 자동완성/공유 시트, 수정 iOS 설치본의 네트워크 동작은 별도 실기기 검증이 필요하다.
