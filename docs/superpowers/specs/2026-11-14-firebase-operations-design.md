# Firebase 이전·비용 보호 설계

사용자가 승인한 출시 준비 2단계. 기존 운영 프로젝트는 couple-diary-75157이며 지금은 Firebase CLI 인증이 없다. 운영 데이터 변경·요금 활성화·보안 규칙 배포 전에 로컬에서 구체적인 도구와 검증 결과를 만든다.

- 테스트/스테이징/운영 공개 설정을 분리한다. 로컬에서 emulator 표시 없이 기존 운영 프로젝트에 연결되는 기본 동작은 차단한다. native 기본 구성은 유지하되 스테이징 빌드는 별도 env와 다른 프로젝트를 필수로 요구한다.
- Git 이력 3493146의 myEntries/{uid}/{date} 형식만 명시적으로 변환한다. 알 수 없는 작성자·날짜·사진 출처·필드 구조는 중단하고 원본을 보존한다. 모호한 예전 '나' 댓글은 수정 불가능한 작성자 ID로 남긴다.
- 커플 단위 이전용 백업은 문서·해당 사용자 사진을 제한된 개수/용량으로 읽고 SHA-256 검증 목록과 함께 저장한다. Auth와 전역 결제 정보는 포함하지 않음을 명시한다. 전체 운영 복구에는 별도 관리형 Firestore export, Auth export, Storage 백업이 필요하다.
- 복구 도구는 기본 미리보기이며 빈 대상 테스트 공간에만 신규 생성한다. 같은 프로젝트나 비어 있지 않은 대상에 덮어쓰지 않는다. 운영 UID나 데이터를 임의로 재생성하지 않는다.
- 실제 이전도 기본 미리보기. 완성된 백업의 원본 해시와 현재 데이터가 일치해야 실행한다. 한번 생성된 대상 일기를 덮어쓰지 않고, 복사·검증 후 schemaVersion=2/status=migrating으로 비공개 전환하고, 사진 토큰을 재시도 가능한 단계로 철회한 뒤 active로 전환한다. 이전 중 삭제 요청은 데이터 변경 없이 일시 중단한다.
- 서버에서 계정 단위 작업 빈도 제한과 사진 업로드 긴급 중지 옵션을 제공한다. 예산 알림과 maxInstances는 청구 상한이 아니라는 점을 문서화한다. App Check는 실제 웹/네이티브 자격 설정 전 강제하지 않는다.

실제 운영 데이터·백업은 외부로 전송하거나 Git에 저장하지 않는다. 도구는 명시적인 프로젝트·버킷과 쓰기 실행 확인을 요구한다. 요금·정책 콘솔 변경은 이 단계에서 수행하지 않는다.

운영비 예산은 사용자가 월 10,000원으로 선택했다. 50/80/100% 사용액과 100% 예측 지출 경고안을 준비한다. 실제 통화·프로젝트 번호·수신 권한 확인 전 생성하지 않는다.
