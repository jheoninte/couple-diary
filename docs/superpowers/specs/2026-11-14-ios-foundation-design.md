# iOS·서버 복구 설계

사용자가 기존 코드 기준 복구와 개발을 승인한 요구사항을 구현한다. 기존 Vite/Capacitor/Firebase를 유지한다. 별도 상시 서버나 다른 데이터베이스로 이전하면 운영 비용과 마이그레이션 부담이 생기므로 선택하지 않는다.

- 무료: 텍스트 일기, 댓글, 기념일, 기존 사진 조회. iOS 배너·전면 광고는 동의와 화면 상태를 확인한 뒤 표시한다. 전면 광고는 저장 완료 후 안전한 화면 전환 시, 최소 저장 3회·10분 간격·하루 2회로 제한한다.
- 우리의 공간 Plus: 월 4,900원, 연 39,900원. 한 명의 유효 구독으로 현재 커플 두 사람 사진·앨범·광고 제거. 실제 결제 가격은 StoreKit 표시값을 사용한다.
- 사진: 기기에서 긴 변 1,440px, 목표 256KiB·최대 512KiB. 서버 예약과 Storage 규칙이 유효 구독·소유권·업로드 횟수를 검증한다. 사용자당 하루 6회·월 90회, 파일당 일회성 예약. 예약 실패도 횟수에 포함해 남용 비용을 억제한다.
- 서버: Node 22 Cloud Functions v2, minInstances 0, maxInstances 2, 모든 쓰기는 인증·멤버십·작성자·revision을 트랜잭션으로 확인한다. 기존 v1 데이터는 자동 덮어쓰기하지 않고 안전하게 중단한다.
- Apple: StoreKit 2 플러그인, appAccountToken과 검증된 JWS 기반 서버 권한. 구성 미완료 시 결제 비활성. 서명 검증·상품·번들·환경·계정 일치 확인 전 권한 지급 금지. Sandbox와 운영 분리.
- iOS: com.interest.couplediary, 앱 이름 우리의 공간. 테스트 AdMob 앱/광고 ID 사용. 지급·세금 정보 변경 없음.
- 운영 변경·유료 서비스 활성화·App Store 제출 없이 로컬 복구와 검증을 먼저 수행한다. 계정 삭제·정책·스토어 설정은 준비 상태를 명시하며 준비 전 출시 점검은 실패해야 한다.

검증: 서버 도메인 회귀 테스트, Firebase 에뮬레이터의 규칙·두 계정 흐름, Vite 빌드, Capacitor 동기화, Xcode 시뮬레이터 빌드. 실제 Sandbox 구매와 광고 계정 상태는 실기기·외부 계정에서 별도 검증한다.
