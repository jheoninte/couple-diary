# 초기 로딩 개선 — 2026-11-20

18개 언어 카탈로그 전체가 초기 i18n 번들에 들어가던 구조를 변경했다. 영어 fallback만 동기 로드하고 한국어는 원문을 사용한다. 나머지 16개 언어는 선택한 언어만 동적으로 로드한다. 언어 원본 TSV와 통합 catalogs.json은 기존 번역 검증을 위해 유지한다.

`node scripts/build-locales.cjs`가 `locales/split/*.json`과 명시적 dynamic import 목록인 `locales/loaders.js`를 생성한다. Vite에서 import attributes가 포함된 가변 경로를 제대로 분석하지 못하므로, 명시적 경로를 유지해야 한다.

## 빌드 크기 비교

Windows / Node 24.22.1 / Vite 7.3.8에서 기존 main 기반 코드와 변경본을 같은 환경으로 비교했다. HTML entry의 정적 JavaScript 의존성을 중복 없이 합산했다. CSS·이미지·런타임 Firebase 요청은 제외한다. 압축 전 크기는 1 kB = 1,000 bytes로 표시했다.

| 초기 JavaScript | 이전 | 이후 | 감소 |
| --- | ---: | ---: | ---: |
| 온보딩 | 966.2 kB | 57.0 kB | 94% |
| 로그인 | 1,524.0 kB | 614.8 kB | 60% |
| 일기 메인 | 1,586.7 kB | 676.5 kB | 57% |

i18n 공유 청크: 964.2 → 53.9 kB. 온보딩 JavaScript gzip 합계: 261.0 → 20.2 kB.

위 표는 한국어·영어 기준이다. 일본어는 별도 언어 청크 55.5 kB (gzip 15.5 kB)가 추가되며 앱 초기화는 해당 파일을 기다린다. 네이티브 앱에는 모든 언어 파일이 포함되므로 앱 설치 크기를 이 비율만큼 줄인다는 뜻은 아니다. 실제 iPhone 실행 시간·LCP는 측정하지 않았다. Firebase 공유 청크 553.3 kB가 다음 주요 검토 대상이다.

## 동작과 검증

- 초기 언어 로드를 마친 뒤 번역 함수를 사용한다. 초기 로드 실패 시 영어로 시작한다.
- 같은 언어의 동시 요청을 합치고, 실패한 요청은 다시 시도할 수 있다.
- 언어 변경 실패 시 기존 언어를 유지한다. 빠르게 여러 언어를 선택하면 마지막 선택만 반영한다.
- 시스템 언어·다른 탭의 설정 변경도 같은 비동기 경로를 사용한다.
- 전체 테스트 119개 통과. 언어 로드 실패·재시도·동시 요청·빠른 전환·RTL·사용자 작성 내용 보존을 검사했다.
- 프로덕션 웹 빌드와 번들 검사 통과. 빌드 검사는 16개 언어 청크 생성, 정적 의존성 분리, 초기 i18n 청크 100 kB 상한을 확인한다.
- 빌드 preview의 온보딩에서 한국어 → 일본어 → 새로고침 → 아랍어 → 영어 → 한국어 전환을 브라우저로 확인했다.
- iOS 동기화·서명 빌드·운영 배포는 수행하지 않았다.
